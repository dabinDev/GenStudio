# 创意工坊积分系统设计

日期：2026-06-10

## 背景

创意工坊已经支持文案、图片、视频三类创作，并区分平台公用模型与用户自定义私有模型。现在需要增加一套积分系统：

- 文案、图片、视频是否扣积分以及扣多少积分，由后台配置。
- 用户自定义模型不扣平台积分。
- 管理员可以在后台为用户增加或扣减积分。
- 积分不足时阻止需要扣费的生成请求。
- 生成失败时需要把已经扣除或冻结的积分退回。

本设计聚焦第一版可上线能力：清晰扣费、可靠退款、后台可配置、用户可查看余额与流水、管理员可审计。

## 已确认规则

1. 用户余额不允许为负数。余额不足时直接拦截请求，并提示用户积分不足。
2. 生成任务失败时自动退回本次预扣积分。
3. 管理员可以增加和扣减用户积分，但必须填写原因。
4. 文案、图片、视频的扣除额度都在后台配置。
5. 用户自己的私有模型不扣平台积分。
6. 公用模型或管理员配置给全站使用的模型按积分规则扣费。
7. 积分价格采用两级配置：能力类型默认价 + 单个公用模型覆盖价。
8. 新注册用户默认 0 积分。
9. 拉新活动可以由管理员配置注册送多少积分。
10. 未登录用户可以看到公用模型；发起需要扣积分的请求时跳转登录，登录后再判断余额。
11. 如果某个公用模型最终计算价格是 0 积分，则允许正常使用，不扣积分。

## 推荐方案

采用“余额快照 + 积分流水账本 + 预扣/退款”的方案。

用户表或用户积分账户表保存当前可用余额，积分流水表记录每一次充值、扣减、生成预扣、生成确认、失败退款、活动赠送。生成请求开始时先预扣积分，任务成功后标记为已消费，任务失败或超时后自动退款。

这个方案比只加一个余额字段更可靠，也比完整钱包系统更轻。它可以满足当前积分需求，同时给后续视频按时长计费、模型差异价格、活动赠送和审计留出空间。

## 数据模型

### 用户积分账户

新增 `user_credit_accounts`：

- `id`
- `user_id`
- `balance`
- `reserved_balance`
- `total_recharged`
- `total_spent`
- `total_refunded`
- `created_at`
- `updated_at`

说明：

- `balance` 表示当前可用积分。
- `reserved_balance` 表示正在生成任务中冻结的积分。
- 第一版可以把余额放在 `users` 表，但推荐独立账户表，避免用户资料字段继续膨胀。

### 积分流水

新增 `credit_transactions`：

- `id`
- `user_id`
- `type`
- `amount`
- `balance_after`
- `reserved_after`
- `capability`
- `model_group_id`
- `sub_model_id`
- `conversation_id`
- `message_id`
- `task_id`
- `related_transaction_id`
- `status`
- `reason`
- `operator_user_id`
- `metadata_json`
- `created_at`

`type` 建议值：

- `admin_adjustment`：管理员增加或扣减。
- `signup_bonus`：注册送积分。
- `generation_reserve`：生成任务预扣/冻结。
- `generation_capture`：任务成功后确认消费。
- `generation_refund`：任务失败后退款。
- `system_adjustment`：系统修正。

`status` 建议值：

- `succeeded`
- `reserved`
- `refunded`
- `failed`

### 积分价格规则

新增 `credit_pricing_rules`：

- `id`
- `scope`
- `capability`
- `model_group_id`
- `sub_model_id`
- `price`
- `enabled`
- `created_by`
- `updated_by`
- `created_at`
- `updated_at`

`scope` 建议值：

- `capability_default`：能力类型默认价格。
- `model_override`：公用模型覆盖价格。

规则：

- 查价时先找当前公用模型的覆盖价格。
- 没有覆盖价格时使用能力类型默认价格。
- 私有模型直接返回 0。
- 价格支持 0 和正整数，不支持负数。

### 注册赠送配置

新增或复用系统设置表，保存：

- `signup_bonus_enabled`
- `signup_bonus_amount`

新用户注册成功后，如果赠送开启且金额大于 0，创建账户并写入 `signup_bonus` 流水。

## 后端扣费流程

### 统一计费服务

新增 `credit_service`，负责：

- 获取或创建用户积分账户。
- 计算某次请求的价格。
- 校验余额是否足够。
- 创建预扣流水并冻结积分。
- 成功后确认消费。
- 失败后退款。
- 管理员调整积分。
- 查询用户余额与流水。

生成接口不直接修改余额，只调用计费服务。

### 文案生成

入口：`/api/proxy/text`

流程：

1. 根据当前模型判断是否为公用模型。
2. 计算价格。
3. 价格大于 0 时要求登录并校验余额。
4. 请求上游前预扣积分。
5. 上游成功返回后确认消费。
6. 上游失败、超时或内部异常时退款。
7. 私有模型或价格 0 时不创建扣费流水。

### 图片生成

入口：`/api/proxy/image` 与 `/api/proxy/image/query`

图片可能同步返回，也可能进入异步任务。流程：

1. 创建图片任务前计算价格并预扣积分。
2. 如果创建接口同步成功并直接返回图片，立即确认消费。
3. 如果返回任务 ID，保存预扣流水 ID 与任务 ID 的关联。
4. 轮询查询成功时确认消费。
5. 轮询查询失败、任务失败、任务不存在、超时清理时退款。
6. 前端看到的失败文案保持用户友好，不暴露系统级错误。

### 视频生成

入口：`/api/proxy/video/create` 与 `/api/proxy/video/query`

视频与图片一样采用任务型计费：

1. 创建任务前预扣。
2. 任务成功后确认消费。
3. 任务失败、查询失败、超时清理后退款。
4. 后续如果要按时长、分辨率、模型价格做差异计费，可以在价格规则里增加 `metadata_json` 或扩展规则表。

## 失败与退款规则

必须退款的情况：

- 上游请求超时。
- 上游返回失败。
- 上游返回非 JSON 或无法解析。
- 任务查询结果为失败。
- 任务不存在或已被清理，但本地仍存在未确认的预扣流水。
- 服务端内部异常导致请求没有成功完成。

不重复退款：

- 每条 `generation_reserve` 只能对应一次 `generation_refund` 或一次 `generation_capture`。
- 退款逻辑必须幂等，重复查询同一个失败任务不会多次返还积分。

用户提示：

- 积分不足：`积分不足，请充值后再生成。`
- 系统失败：`生成失败，请稍后重试。`
- 已退款失败：`生成失败，已退回本次积分。`

后台日志可以保留详细错误，前台不展示上游原始系统错误。

## 管理后台

### 运营面板

增加积分相关指标：

- 总积分余额。
- 今日消耗积分。
- 今日退款积分。
- 公用模型积分消耗。
- 按能力类型统计积分消耗。
- 按模型统计积分消耗。
- 按用户统计积分消耗。

### 公用模型配置

增加积分价格配置：

- 文案默认价格。
- 图片默认价格。
- 视频默认价格。
- 当前模型覆盖价格。
- 是否使用默认价。
- 当前生效价格预览。

模型列表显示：

- 是否公用。
- 当前能力类型。
- 当前生效积分价格。
- 是否有模型覆盖价。

### 用户管理

用户详情抽屉增加：

- 当前余额。
- 冻结积分。
- 累计充值。
- 累计消耗。
- 累计退款。
- 最近积分流水。

操作抽屉增加：

- 增加积分。
- 扣减积分。

管理员调整积分时必须填写：

- 调整数量。
- 调整原因。

扣减时如果可用余额不足，默认不允许扣成负数。

### 积分流水页

可以作为用户管理详情中的子列表，也可以后续独立成一个后台 tab。第一版建议先放入用户详情抽屉，并提供全局筛选入口：

- 用户。
- 类型。
- 能力。
- 模型。
- 时间。
- 任务 ID。
- 状态。

## 个人中心

个人中心展示：

- 当前可用积分。
- 冻结中积分。
- 本月消耗。
- 最近积分流水。
- 积分规则说明。

文案建议：

- `私有模型不消耗平台积分。`
- `公用模型按后台配置扣除积分。`
- `生成失败会自动退回本次积分。`

当用户积分不足时，页面应提供去个人中心或联系管理员充值的入口。

## 前端请求行为

生成前：

- 根据模型信息展示预计消耗积分。
- 如果用户未登录且预计消耗大于 0，点击发送时跳转登录，登录后回到当前页面。
- 如果用户已登录但余额不足，阻止发送并提示充值。
- 如果模型价格为 0 或私有模型，继续现有流程。

生成中：

- AI thinking 动画继续展示。
- 如果是已扣费任务，可以在状态旁显示 `已冻结 N 积分`。

生成后：

- 成功：刷新余额。
- 失败退款：刷新余额并提示已退回。
- 查询轮询命中最终状态时也必须刷新余额。

## 权限与审计

- 只有管理员可以配置积分价格、注册送积分和用户积分调整。
- 所有管理员积分调整都写入 `admin_operation_logs`。
- `credit_transactions` 是账务主记录，不允许物理删除。
- 管理员可以查看流水，但不能修改历史流水。
- 普通用户只能查看自己的余额和流水。
- 后台响应不返回密钥、完整上游请求头或敏感配置。

## API 设计

### 用户接口

- `GET /api/credits/me`
  - 返回当前用户积分账户与最近流水。

- `GET /api/credits/pricing/estimate`
  - 参数：`capability`、`modelGroupId`、`subModelId`。
  - 返回：是否扣费、预计价格、价格来源。

### 管理员接口

- `GET /api/admin/credits/settings`
  - 获取类型默认价格、注册送积分配置。

- `PUT /api/admin/credits/settings`
  - 更新类型默认价格、注册送积分配置。

- `GET /api/admin/credits/transactions`
  - 查询全站积分流水。

- `GET /api/admin/users/{user_id}/credits`
  - 查询某个用户积分账户与流水。

- `POST /api/admin/users/{user_id}/credits/adjust`
  - 管理员增加或扣减积分。
  - 请求体：`amount`、`reason`。

- `PUT /api/admin/models/{model_id}/credit-pricing`
  - 设置或清除单个公用模型覆盖价。

## 数据迁移

迁移步骤：

1. 创建积分账户表、流水表、价格规则表。
2. 为已有用户创建余额为 0 的积分账户。
3. 初始化三类能力默认价格：
   - 文案：0
   - 图片：1
   - 视频：0
4. 不给历史生成记录补扣积分。
5. 如果有已有公用模型，需要默认使用能力类型价格。

默认价格可以在实施时按管理员后台配置调整，不写死在前端。

## 测试计划

后端测试：

- 新用户账户默认 0 分。
- 管理员增加积分成功并写流水。
- 管理员扣减积分成功并写流水。
- 管理员扣减超过余额时失败。
- 私有模型生成不扣积分。
- 公用文案模型按默认价扣积分。
- 公用图片模型按默认价扣积分。
- 公用视频模型按默认价扣积分。
- 单模型覆盖价优先于能力默认价。
- 积分不足时生成请求被拦截。
- 同步生成失败自动退款。
- 异步任务失败自动退款。
- 重复查询失败任务不会重复退款。
- 文案、图片、视频成功后余额正确刷新。

前端测试：

- 个人中心展示余额和流水。
- 公用模型显示预计消耗积分。
- 私有模型显示不消耗积分。
- 积分不足时发送按钮不进入生成流程。
- 登录跳转后能回到原页面。
- 管理后台可以配置类型默认价。
- 管理后台可以配置模型覆盖价。
- 用户详情抽屉可以充值和扣减积分。
- 失败退款后 toast 与余额刷新正确。

## 不在第一版范围

- 积分支付购买。
- 积分过期。
- 套餐订阅。
- 优惠券。
- 多币种。
- 按 token 精确计费。
- 视频按时长、分辨率、模式自动公式计费。
- 团队账户共享余额。

这些能力可以在第一版账本结构上继续扩展。

## 自检

- 本设计覆盖文案、图片、视频三类生成。
- 本设计明确私有模型不扣积分。
- 本设计明确后台类型默认价与模型覆盖价。
- 本设计明确余额不足拦截、失败退款和幂等退款。
- 本设计包含用户端、管理员端、数据模型、API 和测试计划。
- 本设计没有要求在第一版引入支付、套餐或复杂价格引擎。
