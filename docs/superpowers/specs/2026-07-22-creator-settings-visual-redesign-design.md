# 创作工作台与模型设置视觉重构设计

日期：2026-07-22

## 目标

在不改变模型配置、创作请求和权限规则的前提下，统一设置页、文案创作、图片创作和视频创作的视觉语言，并修复设置页“操作/编辑”菜单被下一条模型遮挡的问题。

成功标准：

- 设置列表中的操作菜单始终显示在全部模型行之上，不被相邻行裁切或覆盖。
- 设置页可以快速扫描模型名称、能力、主模型、状态和操作。
- 文案、图片和视频页面共享一致的工作台结构，同时能凭颜色和控件内容立即区分能力类型。
- 公共模型优先使用管理员配置的模型强调色；私有模型使用能力类型默认色。
- 浅色和深色主题保持相同的信息结构与交互位置。
- 桌面端和移动端均无横向溢出、文本遮挡或浮层越界。

## 方案选择

采用“当前结构内的统一视觉重构”。不进行大规模 Vue 组件拆分，也不继续追加互相冲突的零散样式补丁。现有业务状态与事件处理保留，新增一层明确的视觉令牌和少量必要的 UI 状态。

未选方案：

- 局部补丁无法解决当前样式覆盖层过多造成的持续回归风险。
- 完整组件拆分会扩大本次回归范围，且与视觉修复的直接目标不匹配。

## 层叠缺陷

当前每个 `.settings-model-row` 都以 `z-index: 1` 创建独立层叠上下文。“操作”菜单虽然使用更高的 `z-index`，仍被限制在父模型行内部。后渲染的下一行与前一行处于同级层叠上下文，因此会覆盖前一行的菜单。

修复采用受控的打开状态：

- 同一时间只允许一个模型操作菜单打开。
- 打开菜单时，为所属模型行增加明确的打开状态类并抬高整行层级。
- 页面级透明遮罩负责点击外部关闭，Escape 同样关闭。
- 菜单根据可用空间向上或向下展开；移动端使用固定定位的底部操作面板。
- 打开编辑对话框、切换页面或筛选列表时自动关闭操作菜单。

不依赖 `details[open]` 的浏览器隐式状态作为业务状态源，避免菜单层级和可访问状态失去同步。

## 设置页设计

设置页保留顶部摘要、筛选和批量操作，但降低装饰性，强化资产管理语义。

模型列表采用紧凑的单层列表：

- 左侧为选择框、模型图标、名称和简短说明。
- 中部展示能力类型、公共/私有属性、主模型与配置状态。
- 右侧保留“获取模型”“测试”和“操作”。编辑与删除位于操作菜单中。
- 文案、图片、视频分别使用绿色、暖红、蓝色作为默认能力色。
- 公共模型卡片使用 `publicModelAccent(model)` 输出的颜色作为左侧标识、图标底色和关键标签颜色；不使用整卡高饱和背景。
- 状态色只表达成功、警告和错误，不与模型识别色混用。

编辑对话框维持连接密钥、选择主模型、测试与保存三个阶段。浅色主题使用白色表面和清晰边框，深色主题使用深灰表面；两者保持相同尺寸、间距和焦点顺序。底部保存区固定可见，长内容仅滚动主体。

## 创作页设计

三类页面共享以下结构：

1. 顶部模型身份条：模型图标、名称、能力标签、公共模型标签、价格/积分信息和模型说明。
2. 中央内容区：空状态、历史消息或生成结果。
3. 底部创作区：提示词输入、附件、参数和主要提交动作。

模型颜色通过 CSS 自定义属性下发到身份条、模型图标、输入区焦点边框和主操作按钮。公共模型使用管理员颜色；其他模型按能力使用默认色。颜色只用于关键识别点，正文和大面积表面保持中性，避免页面变成单色块。

各能力的差异：

- 文案：减少空状态装饰，突出对话内容、提示词输入和发送动作。
- 图片：参考图入口占据清晰位置，比例、清晰度、数量和 4K 作为紧凑参数组。
- 视频：首帧、尾帧和参考图采用稳定缩略图槽；模式、画幅、时长、清晰度、数量和音频按工作流分组。

桌面端创作区最大宽度保持稳定，避免大屏拉伸；移动端改为单列，参数浮层使用接近全宽的底部面板。

## 视觉令牌

使用一组最终生效的语义令牌控制浅色和深色主题：

- `--surface-*`：页面、面板、浮层和悬停表面。
- `--text-*`：主文字、次文字和弱化文字。
- `--line-*`：普通边框、强调边框和焦点环。
- `--model-accent`：当前模型识别色。
- `--capability-text`、`--capability-image`、`--capability-video`：私有模型默认能力色。
- `--status-*`：成功、警告和错误语义色。

圆角控制在 6 至 8 像素，阴影仅用于浮层和必要的悬浮状态。禁止装饰性光球、大面积高饱和渐变和嵌套卡片。

## 数据与权限

本次不改变 API、数据库或模型权限逻辑。

- 普通用户在设置页仍看不到公共模型。
- 普通用户仍不能编辑、删除、切换或批量操作公共模型。
- 管理员可以管理公共模型。
- 创作页继续显示所有当前用户可用的公共模型，并读取已有强调色元数据。
- 积分赠送通知的持久展示与关闭行为保持不变。

## 错误与边界状态

- 模型图标加载失败时显示能力字母回退，不改变行高。
- 模型名、主模型名和提示信息使用省略与可访问标题，不能撑破布局。
- 菜单靠近视口底部时向上展开；移动端始终在安全区上方显示。
- 空列表、无搜索结果、未配置模型和请求错误使用现有业务文案，重新统一视觉。
- 浮层打开后保持键盘焦点可见，Escape 和点击遮罩均可关闭。

## 测试与验收

实施遵循测试先行：

- 增加源代码/样式约束测试，先证明缺少操作菜单打开层级、能力视觉令牌和统一工作台标识。
- 为操作菜单状态辅助逻辑增加单元测试，覆盖打开、互斥、关闭和展开方向。
- 运行前端 Vitest 全量测试与 TypeScript/Vite 构建。
- 使用 Playwright 检查浅色和深色主题下的设置页、文案、图片和视频页面。
- 检查桌面 1440 x 900、平板 1024 x 768、移动端 390 x 844。
- 对操作菜单与下一模型行执行边界框和层叠验证，并截图确认。
- 使用本机 Docker 完成镜像/服务构建验证后，才允许进入发布步骤。
