# NewUI 多图引用与 R2 资产生命周期设计

日期：2026-07-30

## 目标

在 `newui` 分支完成一次面向生产的体验与资产治理升级：细化创作端和管理端全部实际上线界面；让图片和视频创作最多使用 10 张有编号的参考图，并可在提示词中通过 `@序号` 精确引用；把服务端生成图片改造成“本地 24 小时缓存 + Cloudflare R2 持久副本 + 专用缩略图”的双层资产生命周期；充分验证后发布到 `https://studio.cylonai.cn`。

成功标准：

- 创作端登录、文案、图片、视频、模型设置、个人资料，以及管理端仪表盘、模型、提示词、记录、积分、系统设置、审计和无权限页面均完成细节审计。
- 图片和视频编辑器最多保留 10 张参考图；模型目录声明更低上限时使用更低上限。
- 每张参考图右上角显示稳定且清晰的 `1` 至 `10` 序号，提示词输入 `@` 时可以选择并插入对应引用。
- 有有效 `@序号` 时只向普通参考图参数提交被引用图片；没有引用时保持兼容，提交当前模式下全部参考图。
- 首帧、尾帧等固定角色素材继续按模式必需规则提交，`@` 只增强提示词语义，不破坏模型协议。
- 所有新生成图片都建立可追踪的本地、R2 原图和 R2 缩略图状态；同步失败可重试且不会误删唯一副本。
- 图片创建后 24 小时内优先使用本地缓存；正常完成同步的资产在 24 小时后只返回 R2 原图和 R2 缩略图地址。同步失败属于告警状态，保留唯一副本直到重试成功。
- R2 缩略图可直接用于会话、记录列表和媒体预览入口，列表不再加载完整原图。
- 管理后台可以查看同步策略、状态计数、最近结果和失败原因，并可预览、立即同步或重试失败资产。
- 本地与线上测试、构建、浏览器检查、数据备份、发布和发布后冒烟全部通过。

## 现状与约束

当前创作端是单个 Vue `App.vue`，实际路由状态为登录、文案、图片、视频、设置和个人资料；管理端是 Vue Router 应用。服务端是 FastAPI，生成图片的 base64/data URL 会写入 `generated_assets/`，本地上传回退写入 `uploaded_assets/`，数据库 `generated_assets` 只保存展示 URL 和缩略图 URL，没有存储状态。

生产参考图上传已有 S3 兼容预签名能力，但生成结果尚未形成一致的 R2 生命周期。现有清理任务只按文件修改时间删除目录中的旧文件，无法证明删除前存在 R2 副本。OrangeAPI 的可复用原则是：资产状态机、原子领取、超时恢复、失败退避、先上传校验再删除本地副本、独立的管理状态；不复制其 Go/Ent 实现。

本次遵守以下约束：

- 不修改或部署 `E:\ForkProject\orangeapi`。
- 不在仓库、日志或设计文档中写入 R2 密钥、服务器私钥或生产环境变量正文。
- 保持现有模型适配器的请求字段和首尾帧语义。
- 不把旧 Next.js 迁移参考代码纳入实现。
- 不做与目标无关的大规模组件重写；仅拆出确实可独立测试的引用解析、资产存储和缩略图单元。

## 方案选择

采用“异步双层资产状态机”。生成结果先落本地并立即可用，后台短周期同步 R2 原图和缩略图；本地副本保留到创建时间满 24 小时，展示 URL 由服务端按当前时间和同步状态解析。

未选方案：

- 请求内同步 R2 会把对象存储延迟和故障直接传递给生成响应，降低可用性。
- 完全取消本地缓存不符合一天缓存要求，也无法可靠接住 base64 或短效上游 URL。
- 继续使用目录级定时删除无法表达每个资产是否已成功同步，不具备安全删除条件。

## 前端界面设计

### 全局细化

沿用当前中性、工作台导向的视觉语言，不另做营销式首页。所有页面统一检查并修正：

- 页面标题、工具栏、字段、列表行、对话框和媒体槽的间距、对齐、层级与文本截断。
- 加载骨架、空状态、无搜索结果、失败、重试、禁用、上传中、处理中和成功反馈。
- 键盘焦点、按钮可访问名称、图片替代文本、浮层 Escape/点击外部关闭。
- 1440 x 900、1024 x 768 和 390 x 844 下的溢出、遮挡、触控尺寸和安全区。
- 浅色与深色主题的信息结构一致性；颜色只用于能力识别和状态语义。

创作端保持高频操作紧凑：消息区、素材条和编辑器是主表面，不增加嵌套装饰卡片。管理端保持运维密度：表格、筛选、统计和维护操作按扫描顺序组织。

### 多图素材条

图片与视频创作复用同一套引用交互：

- 全局绝对上限为 10，实际可用上限为 `min(10, modelLimit)`。
- 支持文件选择和拖放；一次选择超过剩余槽位时只接收允许数量并显示明确提示。
- 缩略图使用固定宽高比和稳定尺寸，右上角显示高对比序号，右侧或悬停工具区提供预览和删除。
- 上传任务逐项显示等待、上传、成功、失败状态；单张失败不丢弃其他已成功图片，可单独重试。
- 素材按当前数组顺序编号。删除中间素材后，后续素材重新编号，同时使用解析器原子更新提示词中的有效引用；指向被删除素材的令牌标记为无效并在提交前提示用户处理。
- 首帧、尾帧仍显示角色标签，同时参与可见序号，避免视频编辑器出现两套识别体系。

### `@序号` 引用

新增与框架无关的引用解析模块，负责扫描、校验、重写和选取素材：

- 输入 `@` 或 `@数字前缀` 时，在编辑器附近显示当前素材建议，包含序号、缩略图和文件名。
- 选择建议插入 `@1` 至 `@10`，令牌边界要求其后不是另一位数字，避免把 `@10` 解析成 `@1`。
- 同一序号重复出现只提交一次，提交顺序按素材原顺序而不是文本出现顺序。
- 有至少一个有效引用时，普通参考图字段仅包含被引用素材；没有任何 `@序号` 时提交全部普通参考图，兼容现有用户习惯。
- 无效或已删除序号不静默忽略；编辑器显示错误并阻止提交。
- 发给上游的文本把引用规范化为可读标记，例如 `参考图1`；会话中保留用户原始文本和带 `index` 元数据的资产，历史记录仍能解释引用关系。
- 视频首帧/尾帧属于协议必需素材，即使提示词未引用也按当前模式提交；普通参考图继续遵守精确引用规则。

## 资产数据模型

扩展 `generated_assets`，让一行代表一个可展示资产及其存储生命周期。新增字段：

- `storage_status`：`local_pending`、`syncing`、`r2_synced`、`sync_failed`、`expired`。
- `local_path`、`local_thumbnail_path`：仅保存服务端受控目录中的相对路径。
- `r2_object_key`、`r2_thumbnail_key`：R2 对象键，不保存密钥。
- `r2_url`、`r2_thumbnail_url`：自定义公开域名下的稳定 URL。
- `content_type`、`size_bytes`、`sha256`：上传和校验信息。
- `local_expires_at`：默认创建时间加 24 小时。
- `sync_attempts`、`last_sync_error`、`synced_at`、`storage_updated_at`：重试与运维信息。

增加编号迁移 SQL，并同步更新开发环境幂等建表/补列逻辑。现有行按 URL 类型回填：本地生成 URL 转为 `local_pending`，已经是对象存储 URL 的行转为 `r2_synced`，无法确认的远程上游 URL进入待抓取迁移队列但不删除原 URL。

引用图片在会话资产元数据中保存 `index`、`role`、`source` 和 `objectKey`。数据库序号从 1 开始，与界面一致。

## 存储与缩略图

扩展现有 `storage.py` 为可注入、可测试的 S3 兼容客户端，支持 PUT、HEAD 和稳定公开 URL 构造。签名逻辑继续使用现有 `OBJECT_STORAGE_*` 配置，不创建第二套密钥体系。

图片进入资产管线时：

1. 验证 MIME、扩展名、像素上限和字节上限。
2. 原图写入唯一临时文件，再原子改名到受控本地路径。
3. 使用 Pillow 按 EXIF 方向校正，生成最长边不超过 640 像素、不放大小图的 WebP 缩略图，默认质量 78。
4. 计算原图 SHA-256，创建或更新数据库资产行。
5. 后台任务上传原图与缩略图，分别执行 HEAD 验证。

远程上游图片由后台使用受限 HTTP 客户端抓取：仅允许 HTTP/HTTPS，限制重定向、响应大小、连接/读取超时和图片 MIME；抓取失败保留原上游 URL 并记录错误，不伪造已同步状态。

R2 对象键使用 UTC 日期和资产 ID，形如：

```text
<prefix>/assets/2026/07/30/<asset-id>/original.<ext>
<prefix>/assets/2026/07/30/<asset-id>/thumbnail.webp
```

## 后台同步状态机

应用 lifespan 启动一个可取消的短周期任务，默认每 60 秒执行一批。每个资产通过条件更新原子领取，只有 `local_pending`、到期可重试的 `sync_failed` 或超过领取超时的 `syncing` 能进入本轮；这样即使未来启动多个 worker，也不会正常情况下重复处理同一行。

同步步骤：

1. 原子标记 `syncing` 并记录更新时间。
2. 确认本地原图和缩略图存在；必要时从受控远程 URL抓取和生成。
3. 上传两个 R2 对象并 HEAD 校验字节或可访问性。
4. 一次数据库事务写入对象键、公开 URL、`r2_synced` 和 `synced_at`。
5. 资产满 24 小时且 R2 已验证后删除本地原图和缩略图，并清空本地路径。

失败时恢复为 `sync_failed`，递增次数，保留本地唯一副本并使用 1、5、30 分钟分级退避。同步记录写入结构化日志，但不包含签名 URL 或密钥。

展示 URL 解析规则：

- 创建未满 24 小时且本地文件存在：`url` 使用本地受保护路由，`thumbnailUrl` 使用本地缩略图路由。
- 已同步但未满 24 小时：仍优先本地，R2 URL 作为元数据可用于诊断。
- 已满 24 小时且 `r2_synced`：只返回 R2 `url` 和 R2 `thumbnailUrl`。
- 已满 24 小时但同步失败：不删除本地唯一副本；返回可用本地地址并明确保持失败状态，管理端告警。数据安全优先于机械执行删除。
- 历史记录序列化时动态解析，不能把昨日的本地 URL 永久缓存进 API 输出。

## 管理后台

将“图片缓存清理”升级为“图片存储与同步”，保留原有权限 `maintenance:asset_cleanup`，避免扩大管理员权限面。界面包含：

- 启用同步、同步间隔、批量大小和本地缓存 24 小时策略。
- 本地待同步、同步中、R2 已同步、失败、已过期数量与占用空间。
- 最近一次自动/手动执行时间、耗时、成功数、失败数、释放空间和错误摘要。
- “预览本轮”“立即同步”“重试失败”操作；破坏性本地清理只对已经 R2 验证的过期资产开放。
- 失败资产表格显示资产 ID、来源、创建时间、尝试次数和脱敏错误，可按状态筛选。

设置存储在现有系统设置表。手动操作写入管理员审计日志。旧目录级清理逻辑继续处理没有数据库归属的孤立文件，但默认不删除 24 小时内文件，也不触碰可识别但尚未同步的资产。

## 错误处理与安全

- R2 未配置时启动健康检查返回明确的存储状态；生产环境继续拒绝不完整对象存储配置。
- R2 故障不让已经完成的生成请求变成失败，但后台和管理端必须可见。
- 删除本地文件前必须同时满足 `r2_synced`、原图和缩略图验证成功、缓存到期。
- 文件路由只接受数据库资产 ID或经过净化的文件名，解析后的路径必须位于配置的资产根目录。
- 远程抓取防止访问环回、私网和链路本地地址，避免 SSRF；限制最大字节和图片解码像素，避免内存耗尽。
- 上传界面和服务端都执行 10 张上限校验，不能只依赖浏览器。
- 缩略图失败不回退加载完整原图作为列表缩略图；同步任务重试生成缩略图，详情预览仍可显式加载原图。

## 发布与回滚

本次用户已明确授权完成后发布。发布只针对 GenStudio 广州生产环境和 `https://studio.cylonai.cn`。

发布前：

1. 提交并推送 `newui`，再次执行完整门禁。
2. 备份数据库、`GENSTUDIO_SECRET_KEY`、当前服务端目录、两套前端静态文件和运行镜像/版本信息；验证数据库备份可读取。
3. 验证生产 R2 配置和隔离测试对象，不打印密钥。
4. 应用编号迁移，再部署后端与前端构建；保留可定位的回滚版本。

发布后检查健康接口、登录、文案、图片/视频页面、管理设置、同步任务、R2 原图和缩略图读取。至少创建一个隔离测试资产验证同步状态和 URL 解析，再清理测试数据。若迁移、登录、生成、R2 读取或前端主流程任一失败，按运行手册恢复静态文件和服务端版本；只有迁移本身导致数据错误时才恢复已验证数据库备份。
