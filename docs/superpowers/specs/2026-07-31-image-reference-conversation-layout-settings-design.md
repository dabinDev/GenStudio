# 图片参考、对话布局与设置页精修设计

## 背景

生产环境已确认两个数据流问题：

1. 图片参考上传到 R2 后，请求体携带的是公开 HTTPS 地址；`image-openai` 适配器只会把本地资产和 Data URL 转成 multipart 文件，因此错误地走了普通图片生成接口。
2. 长任务查询同时返回 `images` 和 `assistantMessage.assets`。两者代表同一逻辑图片，但前者保留上游 URL，后者序列化为 R2 URL；前端仅按 URL 字符串去重，导致同一图片显示两次。

界面还有两个明确的呈现问题：对话时间线固定居中且过窄；模型设置页使用了过多嵌套边框，信息层级拥挤。

## 目标

- R2 参考图必须真正作为 multipart 图片传给 `image-openai` 编辑接口。
- 一张生成结果在对话中只显示一次，多张结果按逻辑顺序完整显示。
- 桌面端对话使用主工作区可用宽度，AI 消息靠左，用户消息和头像靠右。
- 同一消息的多张图片保持单行横向排列；空间不足时横向滚动，不纵向堆叠。
- 设置页减少卡片套卡片的边框感，以分组留白、行分隔和轻量状态强调建立层级。
- 保持移动端可用、键盘操作、媒体预览、下载、引用编辑和批量操作不变。

## 后端设计

`ObjectStorageClient` 增加受大小限制的对象读取能力，返回对象字节和内容类型。图片代理仅解析与 `GENSTUDIO_OBJECT_STORAGE_PUBLIC_BASE_URL` 同源的 URL，将 URL 路径还原为对象键后从当前 bucket 读取。任意外部 HTTP 地址不会由服务器下载，避免 SSRF。

`proxy_image` 在选择 `/v1/images/edits` 或 `/v1/images/generations` 前收集三类可编辑参考：本地资产、Data URL、本站 R2 对象。R2 读取放入线程执行，避免阻塞异步事件循环。对象缺失、为空、超过限制或不是图片时返回明确的 400 错误，不静默退回无参考图生成。

非 `image-openai` 适配器继续按现有 JSON 请求格式透传，不改变视频参考图处理。

## 前端数据设计

`assistantMessage.assets` 是已落库、已应用本地/R2 交付地址的权威资产。查询响应中的 `images` 只负责补齐后端资产尚未出现的位置。

合并顺序按 `batchIndex` 优先，否则按数组位置：

- 已有后端资产的位置直接保留后端资产。
- 只有缺失位置才使用 `images` 中对应项。
- 同一来源内部仍按 URL 去重。
- 没有后端资产时完整使用 `images`，兼容旧任务与匿名请求。

这能同时处理单图 R2 地址变化和多图部分落库，不需要比较两个不同域名的 URL 是否指向同一文件。

## 对话布局设计

时间线宽度改为主工作区的 `100%`，只保留稳定的左右内边距。AI 消息使用“左侧头像 + 左侧气泡”，用户消息使用“右侧气泡 + 右侧头像”。文本气泡保持合理最大宽度，含多图的消息允许扩展到可用宽度。

多图容器使用横向网格流：桌面端每张图采用稳定的最小/最大宽度，最多四张保持同一行；窄屏通过横向滚动浏览。单图仍使用紧凑预览，不被拉伸到整行。

## 设置页设计

保留现有高密度模型表格结构，但把每个模型从完整描边卡片改为平面列表行：

- 列表外层只保留一个轻量边界或背景面。
- 普通行主要用底部分隔线区分，去掉四周边框和阴影。
- 模型能力色只作为窄侧标和小型状态提示，不再叠加整行渐变与内描边。
- 主模型选择区减少内层边框，使用柔和底色和间距分组。
- 悬停只改变背景，不抬升整张卡片。
- 移动端继续折叠为单列，并保留操作菜单的固定底部面板。

整体方向是安静、紧凑、可扫描的工作台，而不是装饰性卡片墙。

## 测试与验收

- 后端单元测试：R2 URL 能解析对象键并进入 multipart；非本站 URL 不下载；超限和非图片对象失败；无参考图仍走 generations。
- 前端单元测试：R2 URL 与上游 URL 不同但逻辑位置相同时只保留一个；部分后端多图资产能补齐；纯查询图片保持完整。
- 样式契约测试：时间线全宽、用户/AI 左右对齐、多图横向滚动、设置行扁平化规则存在。
- 完整前后端测试、类型检查与生产构建。
- Playwright 在桌面宽屏、普通桌面和移动端验证图片对话与设置页，无溢出、遮挡、重复图片和控制台错误。
- 发布后用生产账号复验 R2 参考图、单图去重、多图排列和设置页布局。

## 非目标

- 不修改模型目录、积分计费、历史记录数据结构或 R2 生命周期策略。
- 不重新设计模型编辑弹窗和管理后台。
- 不允许服务器下载任意第三方 URL。
